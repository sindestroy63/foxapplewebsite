# ФОХСТОР

Публичный сайт магазина техники Apple в Самаре. Пользователь выбирает товар и вариант, добавляет позиции в корзину и отправляет заявку менеджеру. Онлайн-оплаты на сайте нет.

## Стек

- Next.js `16.2.4`, React `19.2.5`, TypeScript `5.9.3`
- Payload CMS `3.84.1` с PostgreSQL adapter
- PostgreSQL `16-alpine`
- Nginx `1.27-alpine`, Docker Compose
- Lexical, Sharp, Zod; серверная интеграция Telegram Bot API

## Архитектура и структура

Next.js App Router содержит публичный frontend и встроенную админку Payload. Payload использует PostgreSQL, миграции из `src/migrations` и файловое хранилище media volume. Nginx проксирует HTTP/HTTPS на приложение и обслуживает SSL.

```text
src/app/(frontend)/       публичные страницы
src/app/(payload)/        Payload admin, REST и GraphQL routes
src/components/           UI, каталог, корзина и формы
src/actions/              server actions для заявок
src/lib/                  CMS-запросы, типы, корзина, Telegram и утилиты
src/payload/collections/  коллекции Payload
src/payload/globals/      глобальные настройки Payload
src/migrations/           миграции PostgreSQL/Payload
src/seed.ts               seed категорий, справочников, страниц и товаров
src/seed-products.ts      исходный каталог товаров
nginx/                    активный конфиг и шаблоны для SSL/доменов
docker-compose.yml        app + postgres + nginx
```

## Локальный запуск

```bash
cp .env.example .env
docker compose up -d --build
```

Локальные адреса из `docker-compose.yml`:

- `http://localhost:3003` — приложение напрямую;
- `http://localhost` — приложение через Nginx;
- `http://localhost:3003/admin` — Payload CMS.

Для запуска без Docker нужны Node.js/npm и доступная PostgreSQL, после чего применяются обычные `npm install`, `npm run dev`, `npm run typecheck` и `npm run build`. В Docker миграции запускаются при старте, если `RUN_MIGRATIONS_ON_START=true`.

## Каталог, товары и варианты

Товары находятся в коллекции `Products`. Один товар имеет slug, категорию, изображения, цену, статус и вложенные `variants`; вариант получает отдельный SKU и может содержать цвет, память, SIM, размер, чип, диагональ, подключение, материал и размер ремешка. Статусы товара и варианта: `in_stock`, `preorder`, `out_of_stock`. Отдельные товары для конфигураций создавать нельзя: конфигурации хранятся внутри `variants`.

Seed содержит категории:

| Категория | Slug |
|---|---|
| iPhone | `iphone` |
| iPad | `ipad` |
| MacBook | `macbook` |
| AirPods | `airpods` |
| Apple Watch | `apple-watch` |
| PlayStation | `playstation` |
| Аксессуары | `accessories` |
| Б/У техника | `used` |

Справочники характеристик включают цвета, память, SIM, модели устройств, RAM, размеры вариантов, диагонали и подключение. Каталог также поддерживает навигацию и группы брендов через `CatalogNavigation` и `BrandCatalogNavigation`.

## Корзина и заявка

На странице товара пользователь выбирает вариант и добавляет товар в корзину. Корзина хранится в браузере в `localStorage` под ключом `foxapple-cart`; для одинакового товара и конфигурации количество объединяется.

Маршрут `/cart` показывает позиции, варианты, количество и сумму. На этой же странице находится форма оформления: имя, телефон, Telegram, комментарий и согласие на обработку персональных данных. Онлайн-эквайринга и оплаты нет. После отправки корзина очищается, а менеджер связывается с клиентом для подтверждения заказа, наличия и доставки.

Заявка записывается в Payload collection `Leads` с источником `cart_order`, составом корзины и статусами заявки/отправки в Telegram. Сервер отправляет сообщение через Telegram Bot API (`sendMessage`) в чат из `TELEGRAM_CHAT_ID`; токен задаётся через `TELEGRAM_BOT_TOKEN`. Результат фиксируется как `telegram_sent` или `telegram_failed`. Остальные формы сайта создают заявки с собственными источниками (`product_form`, `contact_form`, `repair_form`, `trade_in_form`, `installment_form`).

## Payload CMS

Коллекции: `Users`, `Media`, `Categories`, `Products`, `Leads`, `Pages`, `CatalogNavigation`, а также справочники характеристик и коллекции импорта/обновления цен (`PriceUpdateBatches`, `PriceUpdateItems`, `PriceImportSessions`, `PriceImportItems`).

Глобалы: `SiteSettings`, `SiteAppearance`, `BrandCatalogNavigation`.

Админка доступна по `/admin`. Дополнительные административные разделы: обновление цен `/admin/price-updates`, Trade-In `/admin/trade-in` и навигация каталога `/admin/catalog-navigation`.

## Основные маршруты

- `/` — главная;
- `/catalog` — каталог;
- `/catalog/[categorySlug]` — категория;
- `/catalog/[categorySlug]/[productSlug]` — товар;
- `/cart` — корзина и оформление заявки;
- `/contacts`, `/installment`, `/trade-in`, `/trade-in/catalog`, `/warranty`, `/repair` — сервисные страницы;
- `/offer`, `/privacy`, `/privacy-policy`, `/personal-data-consent`, `/purchase-return` — юридические страницы;
- `/admin` — Payload CMS.


`PAYLOAD_SEED_ON_START=true` включает seed при старте. Seed обновляет контакты, категории, справочники, канонический каталог товаров, страницы и пользователей Payload; для production включайте его осознанно.

## Migrations и seed

Payload настроен на `src/migrations`, `push: false`, и выполняет зарегистрированные миграции из `src/migrations/index.ts`. При необходимости миграции запускаются вручную командой `npm run payload -- migrate`. Seed зарегистрирован как Payload command `npm run seed`; он не является миграцией схемы.

## Production deployment

Compose запускает три сервиса:

- `postgres` — PostgreSQL 16, порт хоста `5433`, volume `postgres_data`;
- `app` — production-сборка Next.js, порт хоста `3003`, volume `media_data`;
- `nginx` — порты `80/443`, reverse proxy, сертификаты из `/etc/letsencrypt` и ACME volume.

Базовый порядок на Ubuntu: установить Docker Engine и Compose plugin, развернуть проект, создать `.env`, задать production URL/секреты/Telegram, затем выполнить `docker compose up -d --build`. После запуска проверить `docker compose ps`, логи app/Nginx и доступность `/admin`.

Production использует `nginx/conf.d/fohstore-all.conf`. Основной домен — `https://xn--n1aagcfji.xn--p1ai` (фохстор.рф); дополнительные домены перенаправляются на него. Сертификаты находятся в `/etc/letsencrypt/live/fohstore-all/`.

В Compose настроены монтирования `.next`, `public` и `scripts` из рабочей папки сервера. PostgreSQL и загруженные через CMS файлы в `media_data` хранятся отдельно от Git. Видео главной находятся в `public/hero`, изображения описаний — в `public/stories`.

Слайдер главной описан массивом `heroSlides` в `src/app/(frontend)/page.tsx`: 13 слайдов, у каждого видео 1920×1080 без звука и постер в `public/hero` (`<id>.mp4`, `<id>.jpg`), заголовок, подпись и ссылка на товар. Порядок слайдов совпадает с порядком в массиве. Новый ролик кодируется в H.264, 30 кадров/с, `+faststart`, постер берётся с 0,5 секунды.

В шапке сайта логотип «ФОХСТОР.РФ» отображается в одну строку жирным шрифтом без подписи: 24 px на компьютере и 18 px на мобильном экране. На экранах до 860 px кнопка «Позвонить» превращается в чёрный круг 38 px с иконкой трубки (`src/components/CallIcon.tsx`), на компьютере остаётся кнопка с текстом; в открытом мобильном меню по центру шапки выводится «ФОХСТОР.РФ». Корзина и оформление заказа сообщают, что стоимость доставки уточняет менеджер; обещания бесплатной доставки и порог суммы не используются. В характеристиках товаров условия доставки не выводятся.

Карточки категорий показывают только изображения; название ссылки доступно через `aria-label`. На главной после «Лучших предложений» идёт блок о магазине (`src/components/StoreAbout.tsx`): заголовок «ФОХСТОР.РФ: Оригинальная техника ближе, чем кажется», список из девяти преимуществ, адрес магазина и фото `public/store/storefront.jpg`; отдельного блока «Преимущества ФОХСТОР» нет. Высота фото на телефонах задаётся через `padding-top` у `::before`, а не через `aspect-ratio`: в Safari контейнер с `aspect-ratio` и абсолютной картинкой схлопывается до нуля. На страницах товаров и категорий форма заявки под описанием не выводится; уведомления о публичной оферте и RuStore сохранены.

На страницах `/trade-in`, `/installment` и `/contacts` формы заявки не выводятся. В контактах сохранены карта, телефон и ссылки на мессенджеры; Telegram использует `public/telegram.svg`, MAX — цветной значок `public/max.png` с официального сайта `dev.max.ru`. Название магазина в контактах и условиях гарантии — «ФОХСТОР.РФ»; заголовок и текст контактов также хранятся в CMS.

Описание в подвале начинается с «ФОХСТОР.РФ — технологии, которые вдохновляют каждый день» (`CONTACTS.aboutText`); на экранах до 640 px абзац занимает всю ширину, разделы и контакты располагаются ниже в двух колонках.

Поле поиска в шапке печатает и стирает подсказки вместо статичного текста (`useTypingPlaceholder` в `src/components/HeaderSearch.tsx`). Анимация останавливается при фокусе, вводе запроса и включённом `prefers-reduced-motion`; если ширина поля меньше 140 px, остаётся статичное «Поиск товаров». На экранах до 860 px шапка двухстрочная: сверху логотип, корзина, круглая кнопка звонка и меню, под ними поиск на всю ширину, поэтому анимация работает и на телефонах. Размер шрифта в поле 16 px, чтобы iOS не увеличивал страницу при фокусе, а выпадающий список результатов остаётся `position: fixed`: с `position: absolute` в Safari его пункты схлопывались до нулевой ширины.

Фид Priceva (`/api/feed/priceva`) собирает название позиции из частей в порядке «модель, чип, SIM, память, цвет» (`src/lib/priceva-offer-name.ts`): у телефонов SIM идёт сразу после модели, например «iPhone 16 Pro Max SIM + eSIM 256GB Чёрный титан». Идентификаторы позиций (`offer id`) от порядка названия не зависят.

Карточка товара на телефонах (до 720 px) компактная, чтобы варианты, цена и кнопка «В корзину» помещались на первый экран: фото высотой от 180 до 240 px с точками-индикаторами вместо миниатюр, без подписи «Карточка товара», примечание про цену идёт под кнопкой. Блок `.detail-info` на телефонах сбрасывает `top: 72px`, который раньше смещал его вниз. На компьютере карточка не менялась.

Под характеристиками товаров выводится «Рекомендуем к покупке»: для PlayStation 5 — опубликованные товары группы `gaming-consoles` с линейкой `Геймпады PS5` или `Аксессуары для PS5`; для iPad — Apple Pencil; для iPhone — зарядные устройства Apple, повербанки и защитные стёкла; для MacBook — Magic Mouse. Фото, цена, наличие и ссылка берутся из каталога; изображения вариантов используются, если общих фотографий нет. В подборку попадают только поддерживаемые группы каталога с рабочим форматом адреса. Товары со статусом «Нет в наличии» остаются с соответствующей отметкой, скрытые товары не выводятся. Блок работает на странице товара и при выборе модели в каталоге, на самих аксессуарах не показывается. Версию Pencil и стекла выбирают в карточке аксессуара: автоматическая проверка совместимости не выполняется. Данные загружает `/api/product-recommendations?productId=…`.

Сравнение товаров: значок весов в шапке рядом с корзиной и кнопка-весы в правом верхнем углу фото на карточках и страницах товаров. Выбранные товары (до 4) хранятся в `localStorage` под ключом `foxstore-compare` и синхронизируются между вкладками (`src/contexts/CompareContext.tsx`). Страница `/compare` берёт данные из `/api/compare?ids=…`. Характеристики собираются из товара и его вариантов, а там, где они не заполнены, из краткого описания: строки вида `· Экран: …`, `· Процессор: …`, `· Камеры: …`, `· Аккумулятор: …`, `· Зарядка: …`, `· Защита: …`, `· Вес: …`, `· ОС: …` разбираются в отдельные характеристики (`parseDescription` в `src/lib/compare.ts`), оперативная память берётся из строки `· Память: … ГБ ОЗУ`. Строки идут в фиксированном порядке (экран, процессор, память, камеры, аккумулятор, зарядка, защита, вес, связь, SIM, система, цвета, остальное, «О товаре»); бренд и линейка показываются только если различаются. Длинные значения обрезаются до четырёх строк, у строки есть кнопка «Показать полностью». Различием считаются только заполненные значения, переключатель «Только различия» оставляет отличающиеся строки. Чтобы сравнение было подробнее, достаточно заполнять в описании товара строки с названиями характеристик в формате `· Название: значение`.

Сравнивать можно только товары одной категории (`productGroup`: смартфоны, планшеты, ноутбуки и т.д.). Первый добавленный товар задаёт категорию списка; товар из другой категории не добавляется, вместо этого показывается подсказка с названием текущей категории, а категория освобождается, когда список пустеет. В `localStorage` лежат пары `{id, group}`; списки старого формата (только id) игнорируются. На странице `/compare` в шапке указана категория, а «Добавить товар» ведёт в каталог этой категории. Логика в `src/lib/compare.ts` (`toggleCompareEntry`, `parseCompareEntries`).

Просмотр фото: нажатие на фото товара (карточка и страница товара) открывает его на весь экран (`src/components/GalleryLightbox.tsx`): белый фон, счётчик «2 / 3» слева, крестик справа, стрелки по краям, миниатюры снизу. Листается свайпом влево и вправо, закрывается крестиком, свайпом вниз, клавишей Escape или нажатием на пустое поле. На компьютере работают стрелки клавиатуры, фокус удерживается внутри окна и возвращается на фото после закрытия. Свайп (`src/lib/use-swipe.ts`) работает и на основном фото в карточке; номер фото синхронизируется между карточкой и просмотром.

## Остатки МойСклад

iPhone Duo не привязан к остаткам МойСклад: синхронизация его не трогает, видимость на сайте и статус («В наличии», «Под заказ», «Нет в наличии») задаются в админке. Раньше скрипт принудительно скрывал его при каждом запуске, из-за чего страница товара отдавала 404, а слайд на главной вёл в никуда.

`scripts/moysklad-stock.mjs` получает полный отчёт остатков МойСклада и обновляет количество, доступность и статус вариантов товаров. Сопоставление учитывает модель, цвет, накопитель, SIM и остальные характеристики конфигурации. Режим `--dry` выполняет расчёт без записи в базу.

На сервере синхронизацию запускают `docker/moysklad-stock.service` и `docker/moysklad-stock.timer`, установленные в systemd. Таймер включён в автозапуск: первый запуск назначен через 15 секунд после загрузки, следующий — через 10 секунд после завершения предыдущего. Служба выполняет скрипт внутри `foxapple-app-1`; одновременные запуски одной службы не пересекаются.
